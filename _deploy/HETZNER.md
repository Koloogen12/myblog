# dkochnev — личный сайт и блог Данила Кочнева

Переехал сюда с Selectel 2026-09-07, после того как тот сервер умер.

## Что это

Vite SPA (React) + админка. **Своей базы нет** — бэкенд внешний, Supabase
(проект `mxttoiqtviaobotoekxw`). Поэтому стек — один контейнер со статикой.

## Раскладка

    /opt/stacks/dkochnev/
      compose.yml          стек, один сервис web (caddy:2-alpine)
      caddy/Caddyfile      вся логика сайта
      site/                собранный dist/, заливается rsync-ом с ноутбука
      tools/               prerender.py, generate-seo-files.py

Секретов на сервере нет: анонимный ключ Supabase публичен по устройству
(его защищает RLS) и вшит в бандл. `/etc/dkochnev/` не нужен.

## Почему логика внутри контейнера, а не в общем Caddyfile

Общий `/opt/caddy/Caddyfile` смонтирован одним файлом, и его правка — это
риск для всех соседей по площадке. Поэтому там только маршрут в две строки,
а всё остальное здесь. Правки сайта общий файл не трогают.

Внутренний Caddyfile лежит **каталогом**, а не одиночным файлом-маунтом —
именно поэтому его можно спокойно перезаписывать чем угодно.

## Что делает внутренний Caddy

1. **`/supabase/*` → `<project>.supabase.co/*`.** Часть российских
   провайдеров режет `*.supabase.co`. Браузер ходит на свой origin, до
   Supabase достукивается уже сервер. Фронт резолвит адрес в рантайме
   (`window.location.origin + '/supabase'`), поэтому одна сборка работает и
   на домене, и на localhost.
2. **Пререндер для краулеров.** SPA рендерится в браузере, а GPTBot,
   PerplexityBot и ClaudeBot JS не исполняют — без снапшотов они видят
   пустую оболочку. По User-Agent отдаём `site/prerender/<путь>.html`,
   собранный из той же базы. Это dynamic rendering, не клоакинг.
3. **Кэш.** `immutable` только на `/assets/*` — там хеш в имени файла.
   Всё остальное `no-cache`: картинки лежат под своими именами, и вечный
   кэш означал бы, что подменённый файл никогда не доедет до браузера.

## Обновление контента

`/usr/local/sbin/dkochnev-refresh` (cron ежечасно, `/etc/cron.d/dkochnev-refresh`)
пересобирает снапшоты и sitemap/rss/llms.txt из живой базы. Скрипты сами
отказываются писать, если база вернула ноль постов, — пустой ответ Supabase
не затрёт рабочие файлы.

## Деплой

С ноутбука: `./_deploy/deploy.sh` из репозитория `github.com/Koloogen12/myblog`.
Заливает `dist/` в `site/` с `--delete`, но **исключает** `prerender/`,
`sitemap.xml`, `rss.xml`, `llms.txt` — их владелец сервер, а не локальная сборка.
